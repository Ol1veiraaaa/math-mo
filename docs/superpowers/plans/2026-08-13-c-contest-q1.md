# C Contest Q1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and independently verify a complete end-to-end Q1 Demo, then use its frozen v0 artifact as the upstream input to the full C-contest Demo while keeping later Q1 model upgrades versioned.

**Architecture:** A schema-validated data layer builds one symmetric historical/future feature contract. A fold registry drives leakage-safe broad screening, constrained tuning, lockbox evaluation, diagnostics, and final retraining. A result registry is the only source for official CSVs and the Q1 review report.

**Tech Stack:** Python 3.12, pandas, NumPy, scikit-learn, CatBoost, LightGBM, XGBoost, Optuna when useful, Matplotlib, Seaborn, SHAP/permutation importance, joblib, pytest, openpyxl.

## Global Constraints

- Implement Q1 only for this plan. First deliver a complete runnable Demo; user review is an evidence checkpoint, not a mandatory stop.
- Keep the official train/test split fixed; never use hidden test rows for selection.
- Use only pre-kickoff features and fail on the forbidden field manifest.
- Keep derived variables limited to the approved theoretically justified manifest.
- Use millions of persons for training and scoring; use persons only for the 72-match official output.
- Use exactly the same split, preprocessing contract, and metrics for all model families.
- Install and lock locally runnable high-performance dependencies; accept models only through validation evidence.
- Keep original files read-only and generate outputs by identifier, never by implicit row order.
